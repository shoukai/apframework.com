# Stance Card

## Article mode

`analysis`

## 分析问题

1. The AI-native SDLC playbook 试图解决传统 SDLC 中的什么问题？
2. 它如何通过六阶段和 artifact 链改变阶段之间的交接？
3. Skills、Hooks、测试反馈和人工审批如何共同构成控制层？
4. Maintain 阶段为什么是一个闭环，而不只是传统运维？
5. 这套模型的适用边界是什么？

## 分析假设

- A1（analysis-hypothesis）：该 playbook 的主要对象不是代码生成本身，而是代码生成加速之后的全流程交付约束。
- A2（analysis-hypothesis）：其可复用的工程抽象是“版本化 artifact + 自动触发 + 人工判断门”，而不是 Claude 专属功能清单。
- A3（analysis-hypothesis）：artifact 链把人和 Agent 的协作界面从对话过程转移到可审阅、可追踪的中间产物。

## 不声明的内容

- 不将“下一代软件开发范式”写成本文作者结论。
- 不把 Anthropic 的采用比例、效果数字和产品状态当作独立事实。
- 不主张所有团队必须一次性部署完整六阶段流程。
